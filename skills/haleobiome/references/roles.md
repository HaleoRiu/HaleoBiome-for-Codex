# 五角色职责与交接

角色是职责边界，调度方式由宿主工具决定。不要在没有实际运行子代理时捏造 session ID、审查时间或独立意见。

| 角色 | 输入和职责 | 可核查产物 |
|---|---|---|
| Supervisor | 用户问题、实测数据概况、核心/领域知识；审核方法适用性、因果边界和最终解释 | 候选分析地图、带依据的方法审查、终审结论 |
| Planner | Supervisor 方法建议、用户约束、环境与数据核验 | 可实施计划、依赖、资源与确认记录 |
| Analyzer | 已批准计划、输入位置与语义 | 项目代码、版本快照、实际运行、结果与图、修复说明 |
| Inspector | 同版本代码/参数/输入清单及逐渐就绪的日志 | 静态检查、独立最小复现、数值复核、分级问题与复审 |
| Visual Reviewer | 实际图像、来源表、用户/期刊呈现要求 | 可读性、颜色/分组/图例/单位/误差条/显著性与表格一致性审查 |

## 调度要点

主助手负责协调、向用户沟通和汇总，不把多个子代理互相等待的链条留给用户处理。每次委派提供：角色目标、输入及版本、允许写入位置、权限/范围、输出路径及完成条件。审查者不需要被告知预期结论；方法论意见引用可核验来源，数据事实引用实际表与运行记录。

五角色不等于五个同时运行的进程。例如有四个槽位（含主助手）时：

- 规划阶段：主助手协调 Supervisor、Planner；按依赖先后交接。
- 计算阶段：释放规划阶段槽位，再运行 Analyzer 和 Inspector；两者应同时可工作。
- 图就绪后：Inspector 与 Visual Reviewer 并行。
- 汇总阶段：Supervisor 根据两类审查终审。

若宿主只支持一个子代理，可由主助手担任 Analyzer，让子代理担任 Inspector；其他角色按阶段执行，并披露哪些审查没有独立代理。只有主助手时属于单助手复核模式，不能标注为五个独立 Agent。

## 方法审查的关键区分

Supervisor 检查方法是否回答问题、样本是否可交换、模型是否可辨识、结论强度是否成立；Inspector 检查代码是否忠实实现所选方法以及结果是否可复现。Visual Reviewer 实际读取图像，并用表格核对呈现。任何角色发现超出自身职责的问题，都应移交，不得放行。

Reviewer 对不可检查的内容标记未验证。例如图片读取失败不能以文件存在代替审图；无法访问论文不能伪造引用或声称文献核验完成。
