# 规划和验收提示

以下是决策提示，不是必做分析清单。根据用户科学问题选择、扩展或省略，记录依据。

## 计划应解决的问题

| 维度 | 需要辨识的条件 |
|---|---|
| 研究问题 | 描述、组间比较、梯度/时间响应、功能潜能、预测、整合或其他明确目标 |
| 输入语义 | 原始计数、比例、覆盖度、长度/深度标准化丰度、绝对定量、已变换值或距离 |
| 设计 | 独立采样单位、重复测量、配对、嵌套、空间/时间、批次、混杂和样本量 |
| 方法前提 | 允许的输入尺度、零值处理、深度/过滤策略、可交换性、秩/共线性与可辨识性 |
| 统计取向 | 主验证和探索问题、检验家族及校正、效应量/不确定性、灵敏度与误判后果 |
| 实施 | 任务所需运行环境、资源、依赖、模块顺序、证据位置和交付要求 |

不为了模板对齐随意重命名/排除样本，或将比例乘大数伪装成原始计数。若两个表样本不同，报告差集，区分技术遗漏与有依据的分析子集选择；影响科学范围的排除应写入计划。

## 按问题选择范围

- 扩增子：结合所需分类层级、特征矩阵、测序深度、引物/区域与系统发育树的可用性决定群落描述、多样性、差异与关联等范围。没有必要输入时不强行使用依赖它的方法。
- 宏基因组：区分分类与功能矩阵、注释单位和数据库版本、分层/非分层通路、标准化方式与未注释比例。物种与通路可以作为不同的检验家族；相关性不能直接证明某类群贡献某功能。
- 纵向/配对：先确认采样单位与设计效应能否估计，选择适当模型或置换方案；不能把所有行视为独立样本。
- 预测/网络/整合：只有用户目标需要且数据支持时纳入。关注数据泄漏、分组划分、稳定性及关联解释，不能因为菜单列出便自动执行。
- 输入不足：说明还缺什么、受影响的问题及可完成的子集。不得假定存在未提供的计数、系统发育树、环境变量或配对关系。

知识库和实时文献共同支持具体方法，不把这里的示例当作完整方法目录。若方法前提不满足，应调整方法或缩小结论并取得适用授权，而不是简单放宽质量条件。

## 交付可追溯性

主要发现对应到：问题 → 批准的方法 → 实际运行版本 → 结果表 → 图 → 审查意见。

保存输入清点、确认计划、代码/命令/环境/参数、数据处理记录、结果表与图、运行和审查状态、修订原因、参考文献与限制。按项目规模选择 Markdown/JSON/YAML 或现有结构，不为了固定模板增加无用记录。

报告包含完整主结果与相关敏感性结果；无显著发现、无变量入选、模型不可辨识、方法不适用、执行失败分别标记，不能混同为“通过”或“没有差异”。列出未完成的问题及下一步需要的输入或决策。

## 设计决策示例：治疗组 × 随访

若同一受试者有基线和随访，“治疗相关变化”需先定义是否比较组间变化差异，再考虑交互项或合适的变化量方案。记录受试者层级与观测层级，核验批次与治疗/时间是否混杂；不能把多次观测直接当作独立样本。置换单位应对应所检验的效应与可交换性，不能把“设受试者分层”视为所有效应的充分处理。

物种相对丰度、通路 CPM 和分层通路表应分别确认语义；分层与非分层汇总如何关联需查来源定义，避免重复计入同一信号。具体方法及软件支持仍需数据、环境和来源核验；缺少证据时保持方案条件性。
