# HaleoBiome

根据 Supervisor 知识库、用户要求、实际输入及采样设计，由五个角色共同形成、执行和审查研究方案。沿用用户的语言。用户当前要求和已给出的授权优先于本 Skill 的默认流程。

## 动态规划

- 用研究问题定义完成标准。Supervisor 建立与项目相关的候选分析地图；Planner 说明每项的拟开展、暂缓或不适用及理由。完整性以已确认问题的覆盖及必要诊断衡量，不以模块或方法数量衡量。
- 不要求预制分析代码。Analyzer 在方案批准后生成项目所需的 R/Python 或其他实现；工具、包、输入格式、统计量和绘图按实际条件选择。可复用经核验的工具，但不套用演示数据的分组、列名、阈值、环境变量或方法菜单。
- 输入可能是计数、相对丰度、标准化物种/基因/通路丰度、距离矩阵、注释和元数据。先确认数值语义和单位，再制定输入校验与方法；不要将整数计数、统一归一化或某个环境表作为全局要求。
- 扩增子、宏基因组、功能与多组学问题按数据证据分别规划。上游 FASTQ 处理不是默认任务；若为实现用户目标必须补做，先说明新增范围。
- 知识库是有条件的判断依据。阅读 [知识地图](references/knowledge-base.md) 中与任务有关的章节，并按需读取用户指定的领域扩展。检索足以支持关键选择的原始文献/官方方法文档，核验适用性、版本和矛盾；不设固定文献数、方法数或强制敏感性分析组合。

## 先确认实际能力

读取 [运行模式与协作协议](references/runtime-and-review.md)。检查文件访问、代码执行、后台进程、子代理、消息/等待/取消、图片读取和文献检索能力，记录实际可用项。

- 有子代理与后台运行工具时，采用真正的五角色协作；角色按阶段调度，不要求五个角色同时占槽。
- 本 Skill 对完整分析明确要求使用可用且获准的子代理进行角色分工。主助手协调任务，按 [角色职责](references/roles.md) 给各角色明确输入、范围和产物。遵守宿主对委派的限制；无法委派时不能声称独立多 Agent 审查。
- 子代理不足时，优先保留 Analyzer 与 Inspector 的独立并行。其他角色可分阶段复用槽位，但写明人员/代理分配。
- 只有单助手时可提供标注为“单助手分角色复核”的方案；若用户要求真实五 Agent，并将其作为验收要求，应说明能力缺口，等待用户选择兼容环境或接受替代。无执行工具则只交付方案/代码草案，不能声称实际分析完成；无读图能力则视觉审查标为未完成。
- 角色不锁定模型名称。沿用宿主与用户已有设置；Visual Reviewer 必须能实际读取图像。

## 从问题到批准方案

1. 明确用户研究问题、数据位置和输出目录、目标比较、图表偏好以及已批准的范围/预算。仅询问影响下一步的缺失信息；先做不依赖答案的只读清点和轻量结构核验。
2. 核验矩阵方向、样本/特征 ID、丰度含义、数据来源、批次、独立样本单位、配对/时间/嵌套、混杂、缺失、空样本及过滤历史。不得因文件名或组别顺序推断数据事实；ID 问题应报告差集和影响，不静默丢样本。质量控制规则应匹配输入语义。
3. Supervisor 用实测清点与知识库形成方法问题和候选范围；Planner 选择可实施的设计。相关决策提示见 [规划与验收](references/planning-and-delivery.md)。
4. 环境审查只查任务所需解释器、包与函数。安装/升级先取得用户授权；已授权清单不重复询问。语言替换需核验模型、变换、置换、估计目标和输出含义，不默认 R/Python 等价。
5. 保存具体分析计划：研究问题、输入语义、模块与依赖、拟用方法及理由、协变量/配对/置换单位、预处理、多重检验家族与校正、探索/验证取向、效应量及不确定性、敏感性分析理由、预计资源、交付与未做事项。Supervisor 审核方法适用性。
6. 以一份具体计划集中确认尚未获批的环境动作、统计取向和范围。正式检验按批准计划执行；同方案技术修复和重跑沿用授权。改变方法、检验家族、样本排除、科学范围或安装项时只确认新增变化。用户明确委托决策的事项记录依据后执行，不重复索取授权。

## 生成、运行、并行审查

采用 [角色职责](references/roles.md) 和 [运行模式与协作协议](references/runtime-and-review.md)。模块按依赖滚动推进；不默认从固定 A1/A2/A3 顺序开始。

- Analyzer 是分析代码唯一写入者。冻结版本、记录输入/参数/命令，并在独立版本目录运行；同时让 Inspector 对同一版本审查。
- Inspector 先做静态检查，再随日志与结果到达做复现/数值核验；发现问题立即反馈给协调者及 Analyzer，不等整轮执行结束。Inspector 在独立临时目录复现，不修改执行中的代码或输入。
- 阻断问题到达时协调者决定安全停止受影响任务；确认进程退出后，Analyzer 生成下一版本并重跑，Inspector 对新版本重新复核。未受影响模块可继续；引用旧结果的下游结果须标记失效并重新计算。
- 图产出后，Inspector 数值复核与 Visual Reviewer 实际读图并行；二者完成后 Supervisor 终审方法落实、结论与证据强度。
- 分开记录运行成功和审查通过。超时、没有反馈或子代理退出均不代表通过。依赖失败时下游标为 blocked/skipped，不能偷偷读取历史结果。
- 重试按预算和问题进展控制；同一阻断连续修订仍未解决时汇总证据与替代路径，不无限重跑，也不擅自削减用户要求。

## 交付

交付已运行代码、复现命令与环境、输入/变换说明、实际结果表、经审查的图、方法与限制、文献依据及已完成/未做清单；把未解决问题和未完成审查单独标出。图中显著性、分组、单位、误差条必须与表格和方法相符。

科学结论区分关联与因果、相对与绝对丰度、功能潜能与实测过程。无显著结果、无变量入选或数据不足都是可报告结果；不为获取显著性事后改变阈值。每个主要结论能追溯到当前版本的结果和审查记录。

支持 ChatGPT 与 Codex 的同一 Skill 格式；具体宿主能力和安装方式见仓库使用说明。读取本文件不会自动授予后台执行、子代理或外部服务权限。
